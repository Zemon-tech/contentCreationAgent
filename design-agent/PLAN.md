# Design Agent — Delivery Plan

Companion to [`spec.md`](./spec.md). The spec is the **what** and the binding
contract; this plan is the **how and in what order**. Where the two ever
conflict, `spec.md` wins and this file must be corrected.

---

## 1. Background & context

The Design Agent turns a block of content text into ready-to-post Instagram
images (single image or carousel) rendered from **hand-authored HTML/CSS
templates**. Copy is written by an LLM (Sarvam) into a schema-validated
`PostPlan`; imagery for designated template slots is generated by a **ComfyUI**
workflow on a remote GPU VM; the two are composited by **headless Chromium
(Playwright)** and normalized to Instagram-valid JPEGs with Pillow. The system
**produces files only** — it never publishes to Instagram.

The pipeline is four typed stages behind an HTTP job API:

```
content text ─► PLANNER (Sarvam) ─► IMAGE ENGINE (ComfyUI) ─► COMPOSITOR (Chromium+Pillow) ─► ASSEMBLER (files)
```

### Current state (already built)

A foundation scaffold exists and passes lint + strict types + tests:

- Tooling: **uv** (env/deps/lock), **Ruff** (lint+format), **mypy --strict**,
  **pytest**+coverage. Config all in `pyproject.toml`.
- `app/config.py` — `pydantic-settings` `Settings` (all §10 env vars, secrets as
  `SecretStr`).
- `app/logging_config.py` — `structlog` + stdlib `ProcessorFormatter` bridge,
  JSON in prod / console in dev.
- `app/exceptions.py` — `DesignAgentError` hierarchy (status + code + safe
  details).
- `app/error_handlers.py` — FastAPI handlers → consistent JSON error envelope;
  unexpected errors return an opaque 500.
- `app/middleware.py` — request-id / structured context binding.
- `app/security.py` — `X-API-Key` auth dependency (constant-time compare).
- `app/main.py` — app factory, lifespan, public `/health` + authenticated `/`.
- `tests/` — 19 passing tests.

### Not yet built (the work this plan covers)

`app/models.py`, `app/templates_loader.py`, `app/brand.py`, `app/sarvam.py`,
`app/planner.py`, `app/images.py`, `app/compositor.py`, `app/assembler.py`,
`app/queue.py`, the `/jobs` routes, `brand.yaml`, one starter template under
`templates/`, and one sample workflow under `workflows/`.

## 2. Constraints

### Hard constraints (from the spec — non-negotiable)

- **No publishing.** Files only. No Meta/Instagram API code.
- **Templates are hand-authored.** The agent fills them; it never generates them.
- **Static images only.** No video/Reels/Stories.
- **Interface is the HTTP endpoint + output folder.** No frontend.
- **Auth is one shared API key.** No multi-tenant/user model.
- **One request → one post.** No scheduling.
- **PostPlan is produced with Sarvam `json_schema` strict**, schema **derived
  from the chosen template manifest** (not a generic schema). Model
  `sarvam-105b`; never `sarvam-30b`.
- **`text_slot.max_chars` is enforced at planning time.** Compositor auto-fit
  only shrinks type — it never edits text.
- **One aspect ratio per carousel.**
- **GPU/ComfyUI jobs are serialized** (single-slot lock; two diffusion jobs
  OOM). **Chromium is one reused browser** with a bounded page semaphore;
  launch once at startup, close on shutdown. Never a browser per request.
- **Brand banned-words scan gates every generation.**
- **Output images are 1080-wide, sRGB, JPEG ≤ ~1.4 MB.**
- **Renderer is Chromium, not SVG** (SVG has no working text wrapping; Sarvam
  output may be Indic and needs HarfBuzz shaping — Chromium does both).
- Secrets from env only; never hardcode or log secret values.

### Environmental constraints & decisions

- **Python 3.12** (installed and pinned; spec says "3.11+", 3.12 satisfies it).
- **ComfyUI**: a reachable **remote** instance is available for development;
  set `COMFYUI_BASE_URL` to it. Unit tests use recorded fixtures so they don't
  depend on the VM.
- **Sarvam**: a real API key is available for a **single gated live
  integration test**; all other planner tests use mocked responses.
- **Brand fonts (DM Sans, Inter, Noto fallback)**: the user supplies the
  `.woff2`/`.ttf` files. The build MUST NOT hard-fail when they are absent
  during development — a placeholder/system fallback is used and a warning is
  recorded. A `templates/_shared/fonts/README.md` documents exactly which files
  to drop where.
- Dev host is Windows; deploy target is Linux GPU VM. Playwright browser
  install differs per OS — captured in Phase 6.

## 3. Key decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Python **3.12** | Installed, working, satisfies spec's "3.11+". |
| D2 | Build **Stage 2 & 3 against mocks/fixtures** for unit tests; live tests gated behind env keys and marked `integration` | Deterministic CI that doesn't depend on the VM or spend Sarvam credits; still verifiable end-to-end on demand. |
| D3 | **Sarvam `response_format` = `{"type":"json_schema","json_schema":{...,"strict":true}}`** | Confirmed supported by Sarvam; guarantees structural validity of the PostPlan before expensive stages run. |
| D4 | **PostPlan JSON Schema is generated at runtime from the chosen manifest** | Spec §5.2/§6.2: constrains slot keys, slide count, and per-slot `maxLength` to that template. |
| D5 | Resolve generated images into templates as **base64 data URIs** | Spec §7.1 preference: renderer needs no file server; fully self-contained HTML. |
| D6 | **Job queue = in-process `asyncio.Queue`** + worker pool (default 1); ComfyUI behind a **single-slot lock**; Chromium behind an **`asyncio.Semaphore`** | Spec §9. GPU is the bottleneck; keep it simple and in-process. |
| D7 | **Persistent browser** launched in FastAPI lifespan, stored in app state, closed on shutdown | Spec §9. Never per-request. |
| D8 | Font files are a **runtime asset, not a code dependency**; missing fonts degrade gracefully with a recorded warning | User supplies fonts later; development must not be blocked. |
| D9 | One starter template **`keilhq-editorial`** (portrait 4:5, single+carousel) and one sample workflow are deliverables | Build Order step 2 needs a real template to prove the compositor; gives the coding agent a concrete reference. |
| D10 | **Placeholder image provider** (solid brand-color PNG) used until ComfyUI is wired | Lets the compositor and full pipeline be proven before any GPU work (Build Order step 2). |
| D11 | Each stage is a **pure-ish function over typed Pydantic models**; no stage reaches into another's internals | Spec §3. Makes each stage independently testable. |
| D12 | Test layout mirrors `app/`; live/slow tests marked with a pytest `integration` marker, skipped unless keys present | Fast default suite; opt-in integration. |

## 4. Phase-wise TODOs

Order follows the spec's Build Order (§16). Each phase is independently
verifiable; **verify by inspecting real output, not just "no error"**.

### Phase 0 — Contracts, config surface, brand loader
Foundational data + loaders. No pipeline behavior yet.

- [x] `app/models.py`: Pydantic v2 models for the template manifest (§5.1),
      `PostPlan` + `PostPlanSlide` (§5.2), and `PostManifest`/post.json (§5.3),
      plus the API request/response models (§4). Enums for `format`,
      `aspect_ratio`, `text_slot.role`, `image_slot.fit`, job `status`.
- [x] `app/brand.py`: load and validate `brand.yaml`; expose `voice`,
      `banned_words`, `colors`, `typography`; `build_prompt_rules() -> str`;
      `scan_banned_words(texts) -> list[hits]` (case-insensitive).
- [x] Ship `brand.yaml` exactly as in spec §8.
- [x] `app/templates_loader.py`: discover templates under `TEMPLATES_DIR`,
      validate each `manifest.json` against the manifest model, expose
      `list_templates()` and `get_template(id)`.
- [x] `build_postplan_schema(manifest) -> dict`: generate the strict JSON
      Schema from a manifest (slide count bounds, per-slot keys, `maxLength` =
      `max_chars`, required `prompt_slot` image keys).
- [x] Extend `.env.example` if any new knobs appear (none expected).
- [x] Tests: manifest validation (valid + malformed), schema generation asserts
      `maxLength`/required/`minItems`/`maxItems`, brand loader + banned-word
      scan.

**Exit:** `build_postplan_schema` output inspected and correct for a sample
manifest; brand loader round-trips `brand.yaml`.

### Phase 1 — Starter template + fonts scaffold
The hand-authored asset the compositor renders.

- [x] `templates/keilhq-editorial/manifest.json` — portrait, supports
      `single` + `carousel`, 4:5 (+3:4, 1:1), text slots (eyebrow, headline,
      body, cta) with real `max_chars`, one `background` image slot
      (`prompt_slot: true`, cover).
- [x] `templates/keilhq-editorial/template.html.j2` — one `#canvas` sized to the
      exact target pixels; brand tokens as CSS custom properties; a centered
      safe zone; `@font-face` for DM Sans/Inter with Noto fallback stack.
- [x] `templates/keilhq-editorial/style.css`.
- [x] `templates/_shared/fonts/README.md` — exact filenames the user must add
      (e.g. `DMSans-Bold.woff2`, `Inter-Regular.woff2`, `NotoSans-Regular.ttf`)
      and where. Code falls back gracefully + warns if missing.
- [x] Tests: manifest loads and validates; HTML renders as a Jinja2 string with
      a sample context (no browser needed here).

**Exit:** template validates through Phase 0's loader; renders to an HTML string
with placeholders.

### Phase 2 — Compositor with placeholder images (highest-risk; do early)
Prove a valid, on-brand JPEG before any AI.

- [x] `app/compositor.py`:
  - Jinja2 render (context: text, image data URIs, brand tokens, aspect).
  - Persistent Playwright browser handle (injected; lifecycle in Phase 5).
  - Render per slide: viewport = exact pixels, `deviceScaleFactor: 1`,
    `set_content(..., wait_until="load")`, `await document.fonts.ready`, then
    screenshot the `#canvas` element (§7.1).
  - Overflow auto-fit: shrink font-size to a CSS floor, warn if still
    overflowing; **never edit text** (§7.3).
  - Pillow normalize: exact dimensions, sRGB/RGB, JPEG q88 → step down to 72 to
    stay ≤ 1.4 MB (§7.4).
  - Placeholder image provider: solid brand-color PNG data URI (D10).
- [x] Bounded concurrency via `asyncio.Semaphore(RENDER_CONCURRENCY)`.
- [x] Tests: given a manifest + fixed copy + placeholder image, output is a
      1080×1350 sRGB JPEG ≤ 1.4 MB; overflow path records a warning; carousel
      keeps one aspect ratio.

**Exit:** a real JPEG on disk, opened and eyeballed for brand fidelity.

### Phase 3 — Planner (Sarvam) + brand enforcement
Content text → validated PostPlan.

- [x] `app/sarvam.py`: thin async client. `POST /v1/chat/completions`, header
      `api-subscription-key`, `response_format` strict `json_schema`, model from
      config, `temperature=0.3`. Typed request/response; raise `PlanningError`
      on transport/HTTP faults.
- [x] `app/planner.py`:
  - Template selection when `template_id` omitted (small json_schema call over
    `{id,name,description,supports}`), validated against requested
    format/aspect (§6.1).
  - Build schema from manifest (Phase 0), call Sarvam, parse into `PostPlan`.
  - Validate against manifest: slots present + within `max_chars`, slide count
    in bounds, every `prompt_slot` has a prompt, hashtags ≤ 30, caption ≤ 2200.
  - Banned-word scan → treated as validation failure.
  - **Retry exactly once** with errors appended; second failure → `PlanningError`
    (§6.5). Never silently truncate copy.
- [x] Tests: mocked Sarvam happy path → valid PostPlan; over-`max_chars` →
      retry then fail; banned word → retry then fail; template auto-select.
- [x] **Gated live test** (`integration`, skipped without `SARVAM_API_KEY`):
      real content → schema-valid PostPlan.

**Exit:** mocked planner produces a PostPlan that composites (Phase 2) with
placeholders; one live call verified manually.

### Phase 4 — ComfyUI image engine
Replace placeholders with generated imagery.

- [x] `app/images.py`:
  - Load API-format workflow + companion `<workflow>.map.json`; inject prompt +
    per-request seed + dimensions via the map (never hardcode node IDs) (§11.2).
  - `POST /prompt` with `client_id`; `node_errors` → `ImageGenerationError`
    (not retryable).
  - Wait via WebSocket: done when `executing` with `node == null` and matching
    `prompt_id`; ignore binary frames; enforce `COMFYUI_TIMEOUT_S` (§11.5).
  - Fetch via `GET /history/{id}` → `GET /view`; save PNG keyed by
    slot+slide index.
  - All calls under the **single-slot GPU lock** (§9).
- [x] `workflows/keilhq-bg.json` (+`.map.json`) — sample workflow for the
      starter template's background slot. (Author against the reachable VM.)
- [x] Tests: workflow injection sets the right node inputs; `node_errors` →
      error; WS completion parsing (recorded fixtures); timeout path.
- [x] **Gated live test** (`integration`): submit workflow to the remote VM,
      receive a PNG.

**Exit:** starter template composited with a **real generated background** from
the remote ComfyUI.

### Phase 5 — HTTP API, job queue, assembler
Wire the stages behind the async job API.

- [x] `app/assembler.py`: write `OUTPUT_DIR/<job_id>/` — `slide_NN.jpg`,
      `caption.txt` (caption + blank line + `#`-prefixed hashtags),
      `post.json` (§5.3, incl. `source_content_sha256`, `warnings`),
      `plan.json`. Enforce Instagram validation (§12): hard dimension violation
      → fail; soft issues → `warnings`.
- [x] `app/queue.py`: in-process `asyncio.Queue`, worker pool
      (`JOB_WORKERS`, default 1), in-memory job status store, status
      transitions `queued → planning → generating_images → compositing → done |
      failed`.
- [x] `/jobs` routes in `app/main.py`: `POST /jobs` (validate body — content
      non-empty ≤ 20000 chars, `max_slides` cap 10 — enqueue, return `202` +
      `job_id`); `GET /jobs/{id}` (status + post when done); all behind
      `X-API-Key`.
- [x] Wire persistent Playwright browser + queue workers into the FastAPI
      lifespan (D7); update `/health` (already ComfyUI-aware).
- [x] Tests: `POST /jobs` → 202; bad body → 422; auth required; a full
      **mocked** run (mock Sarvam + placeholder images) drives
      `queued → done` and writes a valid output folder.

**Exit:** one `POST /jobs` with mocked AI produces a complete, valid output
folder; status polling reflects real transitions.

### Phase 6 — Deployment hardening
Make it run on the Linux GPU VM.

- [x] Playwright: `playwright install --with-deps chromium`; launch flags

- [x] Document OS fonts: `fonts-noto-core`, `fonts-noto-cjk`,
      `fonts-noto-color-emoji` (fallback safety net; brand fonts still embedded).
- [x] Confirm concurrency caps: GPU single-slot lock + render semaphore honored

- [x] Deployment notes in README (env, process memory cap, ComfyUI is external).
- [x] Optional: `Dockerfile` from `mcr.microsoft.com/playwright/python`.
- [x] **Full live end-to-end** on the VM: real content → real Sarvam → real

**Exit:** full pipeline runs on the VM against live Sarvam + ComfyUI and writes
correct, inspected output.

## 5. Definition of Done (whole project)

The project is **done** when all of the following hold:

**Functional**
- [x] `POST /jobs` accepts content, returns `202` + `job_id`; `GET /jobs/{id}`
      reports accurate status through to `done`/`failed`.
- [x] A completed job writes `OUTPUT_DIR/<job_id>/` containing `slide_NN.jpg`
      (1+ slides), `caption.txt`, `post.json`, `plan.json`, matching §13.
- [x] Every output JPEG is exactly 1080-wide (1080×1350 / 1080×1440 / 1080×1080),
      sRGB, ≤ 1.4 MB; carousels use one aspect ratio.
- [x] PostPlan is produced via Sarvam strict `json_schema` derived from the
      chosen manifest; `max_chars`, slide-count, hashtag (≤30) and caption
      (≤2200) limits enforced; over-limit → one retry → clean failure (no silent
      truncation).
- [x] Banned-word scan blocks generation (retry once, then fail).
- [x] Image slots with `prompt_slot: true` are filled by the remote ComfyUI
      workflow; jobs serialized on the GPU lock.
- [x] Compositor auto-fit shrinks type only, records a warning at the floor,
      never edits text.
- [x] `X-API-Key` gates every non-public route; `/health` reports ComfyUI
      reachability.
- [x] One hand-authored starter template + one sample workflow are present and
      exercised end-to-end.

**Quality gates**
- [x] `uv run ruff check .` clean; `uv run ruff format --check .` clean.
- [x] `uv run mypy` clean under `--strict`.
- [x] `uv run pytest` green; **line coverage ≥ 80%** overall.
- [x] Fast suite passes with **no network** (Sarvam/ComfyUI mocked);
      `integration`-marked live tests pass on demand with keys present.
- [x] Full live end-to-end verified on the VM with output JPEGs inspected by a
      human (Phase 6 exit).

**Documentation**
- [x] `README.md` covers local dev + VM deployment (Playwright, fonts, env,
      ComfyUI-is-external, memory cap).
- [x] `templates/_shared/fonts/README.md` lists the exact font files to supply.
- [x] `PLAN.md` phase boxes checked; any spec deviations reflected back into
      `spec.md`.

**Explicitly NOT required** (out of scope, must remain absent): any
Instagram/Meta publishing, agent-generated templates, video, a frontend UI,
multi-user auth, scheduling.

## 6. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Templated output looks generic/off-brand | Phase 2 is first real deliverable; inspect the JPEG before any AI. One good template beats many. |
| Missing font files block development | D8: graceful fallback + warning; fonts are a runtime asset, not a code dep. |
| Indic text mis-shapes | Chromium + Noto fallback in the font stack; verify with a non-Latin sample in Phase 2. |
| ComfyUI/Sarvam flakiness in CI | D2/D12: mocks + fixtures for the fast suite; live tests gated + opt-in. |
| GPU OOM from concurrent diffusion | D6: single-slot lock, enforced and tested under burst (Phase 6). |
| Orphaned Chromium processes | D7: one persistent browser, pages closed after use, closed on shutdown. |
| Carousel slides cropped by Instagram | One aspect ratio per carousel enforced in compositor; safe-zone in template. |
