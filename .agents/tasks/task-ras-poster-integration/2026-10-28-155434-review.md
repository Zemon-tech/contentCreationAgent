# RAS Poster Story template integration

Adds a cutout-poster post format to the in-process Satori renderer: a new `RasPosterStoryTemplate` (3-line Anton headline over cream grid paper with a background-removed hero cutout), the `Postertools` pipeline that produces its props, and a `renderRasPosterStoryTool` Mastra tool wired into `src/mastra/index.ts`. Two foundation fixes land alongside it: an ambient `sharp` type shim that clears the repo-wide TS7016 baseline, and the re-enabling of the Anton font through the existing cwd-safe font loader. The change ships offline-safe: the demo and the tool both render with no logo binary present, falling back to a text wordmark, and the demo avoids the 140MB background-removal model by feeding an already-transparent hero.

Watch for: nothing blocking. The hero cutout path in `Postertools` still pulls the 140MB `@imgly/background-removal-node` model for any non-transparent source (confirmed) — fine for the tool, but a consideration for anywhere it runs on cold input. The `CHAR_EM = 0.44` width heuristic in copy-fit is an approximation measured on test renders (confirmed, by the author's own note), so pathological letter mixes could still overflow the pill.

**Verdict**: APPROVED

## High-level view

The sharp type gap is fixed with a narrow re-export shim rather than a blanket module declaration. `declare module "sharp"` imports the package's actual shipped `dist/index.d.cts` and re-exports the default factory plus the named type members (`Sharp`, `Metadata`, `OutputInfo`, `SharpOptions`, `ResizeOptions`). Types are preserved, not erased — the chained `sharp(...).rotate().resize()` calls and `sharp(buf).metadata()` in `Postertools` all type-check, and `typecheck` runs clean at 0 errors.

Anton is registered the cwd-safe way. It is a single row appended to the `FONT_SPECS` array in `renderer/fonts.ts` with family exactly `Anton` and weight `400`; `loadFonts()` resolves it through `getFontsDir()` + `readFileSync`, so there is no module-top-level cwd-relative font read that could crash boot under Mastra dev's `src/mastra/public` cwd. The woff binary is committed and the README documents it.

The render tool mirrors the existing `renderRasStoryTool` and is registered in the Mastra tools map. It resolves the black raster logo only when a PNG actually exists on disk, and otherwise strips the logo props so the template draws its "Rise & Shine" wordmark — which is the path that actually executes today, since the repo ships only SVG brand assets. It is non-throwing on bad copy or image input, surfacing `ready`/`problems` instead of raising.

The poster template is deliberately kept out of the external Design Agent `template_id` union. `design-tools.ts` carries a comment stating `ras-poster-story` is an in-process Satori template and must never be added to that enum, and no external enum was touched.

The demo asserts a real PNG (signature bytes `89 50 4E 47`) and that Anton weight-400 is loaded, and it exits non-zero on any assertion failure. It passed: 81852-byte PNG, Anton present, no logo binary. The existing `ras:render:test` still renders a correct 1080x1350 story PNG — the story path is unbroken.

### sharp shim: narrow re-export, not a blanket declaration

The concern with any `declare module "sharp"` shim is that it quietly types the whole package as `any` and erases real safety. This one does not. It imports the declarations sharp actually ships:

```ts
declare module "sharp" {
  import * as sharpNs from "sharp/dist/index.d.cts";
  const sharp: typeof sharpNs;
  export default sharp;
  export import Sharp = sharpNs.Sharp;
  export import Metadata = sharpNs.Metadata;
  export import OutputInfo = sharpNs.OutputInfo;
  export import SharpOptions = sharpNs.SharpOptions;
  export import ResizeOptions = sharpNs.ResizeOptions;
}
```

The root cause is real and correctly diagnosed in the header comment: sharp 0.35.5's `exports` map points the ESM type entry at `dist/index.d.mts`, which is not in the installed build — only `dist/index.d.cts` ships, which uses `export = sharp` (a callable function merged with a namespace). Re-exporting it under the bare specifier restores both the default factory and the named members. The proof is in the consuming code: `Postertools` chains `sharp(raw, { failOn: "none" }).rotate().resize(...)`, `sharp(buf).metadata()`, and `.toBuffer({ resolveWithObject: true })`, and `lib/image/validate.ts` imports `Metadata` as a type — all under `typecheck` at 0 errors (confirmed by running it). The baseline was 6 TS7016 errors; it is now 0.

### Anton registration stays on the cwd-safe path

The environment note is explicit that a module-top-level `readFileSync("node_modules/...woff")` previously crashed boot because Mastra dev's cwd is `src/mastra/public`. The change avoids that trap entirely: Anton is one more entry in `FONT_SPECS`,

```ts
{ file: "Anton-Regular.woff", name: "Anton", weight: 400 },
```

and `loadFonts()` reads every spec through `join(getFontsDir(), spec.file)`, where `getFontsDir()` resolves from the module URL, not the process cwd (confirmed). Family is exactly `Anton`, weight `400`, style applied uniformly as `normal` — which matches `DISPLAY_FONT = "Anton"` and `fontWeight: 400` on the three headline tiers in the template. The woff is a committed 15632-byte binary and the README row was added.

### Logo fallback is the live path

```
logoPath("ras-logo-black.png") exists?
   ├─ yes → loadLogoAsset() (sharp reads the raster PNG)
   └─ no  → { logoBase64: "", logoWidth: 0, logoHeight: 0 }
                    │
                    ▼  tool deletes logoBase64/Width/Height from props
         template:  logo ? <img> : <div>Rise & Shine</div>
```

This matters because the repo ships only SVGs under `assets/RAS-by-keilhq`, and `loadLogoAsset` reads a raster PNG via sharp (it throws on an SVG). So the `existsSync` guard is not defensive padding — the else branch is what actually runs today, and the template's gate (`logoBase64 && logoWidth && logoHeight`) correctly resolves to the wordmark. The demo exercises exactly this path and confirms "no logo binary present." Good call keeping the guard on disk existence rather than hardcoding `src/mastra/lib/public/...`.

### Import specifiers

The render chain (`ras-render-tools.ts`, `Postertools.ts`, the template) uses `.js` specifiers throughout, per repo convention. The demo (`rasPosterRenderTest.ts`) and `index.ts` use extensionless specifiers — but that matches the existing `rasRenderTest.ts` and `index.ts` in the repo (bundler resolution + tsx), so it is consistent, not a regression.

### Verification run

`npm run typecheck` → 0 errors. `npm run ras:poster:test` → exit 0, 81852-byte PNG with valid signature, Anton present, no logo binary (wordmark fallback). `npm run ras:render:test` → exit 0, correct 1080x1350 story PNG, existing path unbroken. The GLib-GObject stderr lines during render are harmless native-lib warnings and do not affect exit status (confirmed: exit 0 on both render runs).
